AI Hiring Manager POC

Interview preparation and resume talking points

1. One-minute explanation

I built a retrieval-augmented hiring assistant that compares candidate resumes against a target job description while grounding the recommendation in hiring governance and AI usage policies. A recruiter enters a role such as AVP Collections Analytics. The system retrieves relevant job-description, policy, and resume passages, filters weak resume matches, and asks an LLM to produce ranked candidates, strengths, gaps, and a fit score.

Business value: reduce manual resume screening time while keeping recommendations traceable to source documents and constrained by hiring policy.

3. How the implementation works

Ingestion and indexing

  • PyPDFLoader reads resumes and TextLoader reads policies and job descriptions.
  • Metadata records the source folder and file name, which enables separate retrieval by document type.
  • Documents are split into 500-character chunks with 50-character overlap.
  • all-MiniLM-L6-v2 creates local embeddings and Chroma persists the searchable index.

Retrieval and decision support

  • Job descriptions and policies contribute two relevant chunks each.
  • Up to eight resume matches are retrieved with similarity scores; scores below the configured threshold of 1.2 are retained because Chroma distance is lower-is-better in this implementation.
  • The final prompt explicitly says to use only supplied context and to report when no strong candidate exists.
  • The Streamlit app exposes the role input and renders the recommendation without exposing raw retrieval complexity to the recruiter.

4. Important design decisions

DecisionReason
Separate retrieval filtersPrevents policy, job-description, and resume evidence from being mixed indiscriminately.
Local embedding modelReduces API cost and keeps the indexing path suitable for sensitive resume data.
Similarity thresholdProvides a conservative "no suitable candidates" path instead of forcing a ranking.
Grounded promptRequires evidence-based strengths, gaps, and a fit score rather than unsupported claims.
Interview answer: "I treated the model as a synthesis layer, not the source of truth. The source of truth is the retrieved resume, job, and policy context. That separation makes the system easier to audit and safer to evolve."

5. Risks and production improvements

  • Resume ranking can encode historical or representation bias; production use needs fairness testing, human approval, explanations, and no automatic rejection.
  • The fixed threshold of 1.2 should be calibrated against labeled hiring examples rather than treated as a universal value.
  • PII should be minimized in prompts and logs, with access controls, encryption, retention rules, and audit events.
  • Production retrieval could add hybrid keyword plus vector search, reranking, document versioning, and evaluation sets.
  • The current project requires an OpenAI key for generation; a production design should define a private model or approved gateway fallback.

6. Likely interview questions

Why use RAG instead of asking an LLM to read every resume?

RAG limits the context to relevant passages, preserves source metadata, reduces token usage, and makes it possible to retrieve policies and job requirements separately from candidate evidence.

How do you prevent hallucinated hiring claims?

The prompt restricts the answer to retrieved context, the system can return no-match output, and the UI result should be treated as decision support requiring recruiter review. In production I would add citation spans and structured evidence for every recommendation.

Why is the score threshold important?

A ranking always produces an answer, even when all candidates are poor matches. Thresholding introduces abstention, which is safer for a hiring workflow. The threshold must be tuned using validation data.

What would you measure?

Recall of qualified candidates, precision of top-k recommendations, abstention quality, recruiter acceptance rate, explanation faithfulness, latency, cost, and fairness metrics across relevant groups.
